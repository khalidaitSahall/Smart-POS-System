🛒 نظام الكاشير وإدارة المبيعات المتكامل (Smart POS System)

نظام نقاط بيع (Point of Sale) وإدارة مخزون شامل مصمم خصيصاً للمحلات التجارية، يجمع بين السرعة في الأداء، سهولة الاستخدام، والقدرة على العمل بدون إنترنت (Offline-First) مع المزامنة السحابية التلقائية.

🎯 نظرة عامة على النظام

يهدف هذا المشروع إلى أتمتة جميع العمليات اليومية داخل المحل التجاري، بدءاً من مسح المنتجات بالباركود، إصدار الفواتير، إدارة الديون (الكريدي)، وصولاً إلى جرد المخزون واستخراج تقارير الأرباح الدقيقة لصاحب المحل.

✨ الميزات والوظائف الرئيسية

1. واجهة الكاشير ونقطة البيع (POS Interface)

سرعة فائقة: دعم كامل لقارئ الباركود (Barcode Scanner) واختصارات لوحة المفاتيح.

إدارة الفواتير: إمكانية تعليق الفاتورة (Hold Bill) لخدمة زبون آخر، وإرجاع المنتجات (Refunds).

تعدد طرق الدفع: نقدي (Cash)، بطاقة بنكية، أو الدفع الآجل (تسجيل على حساب الزبون).

الخصومات والضرائب: تطبيق خصم على مستوى المنتج الواحد أو الفاتورة كاملة.

2. إدارة المخزون والمنتجات (Inventory Management)

تصنيف المنتجات: تقسيم المنتجات حسب الفئات، العلامات التجارية، والوحدات (قطعة، علبة، كيلوغرام).

تنبيهات ذكية: إشعارات تلقائية عند وصول المنتج للحد الأدنى أو قرب انتهاء الصلاحية.

توليد الباركود: إنشاء وطباعة ملصقات الباركود للمنتجات التي لا تحتوي عليه.

3. إدارة العملاء والموردين (CRM & Suppliers)

سجل الديون (الكريدي): تتبع المبالغ المستحقة على الزبائن وإصدار كشوفات حساب.

فواتير المشتريات: تسجيل البضائع الواردة من الموردين وتحديث متوسط التكلفة تلقائياً.

4. التقارير والتحليلات المالية (Reports & Analytics)

إغلاق الصندوق (Z-Report): مطابقة النقد الفعلي في الدرج مع مبيعات النظام نهاية اليوم.

تقارير الأرباح: حساب صافي الربح (سعر البيع - سعر التكلفة - المصاريف).

حركة الأصناف: معرفة المنتجات الأكثر مبيعاً والمنتجات الراكدة.

5. الأمان والصلاحيات (Security & Roles)

نظام صلاحيات دقيق (RBAC): فصل صلاحيات الكاشير (بيع فقط) عن المدير (تعديل الأسعار، حذف الفواتير، الاطلاع على الأرباح).

سجل النشاطات (Audit Log): تسجيل كل حركة حساسة يقوم بها أي مستخدم مع الوقت والتاريخ.

💻 المتطلبات التقنية والأجهزة

الأجهزة المطلوبة (Hardware)

حاسوب مكتبي أو شاشة لمس (Touchscreen POS Terminal).

طابعة فواتير حرارية (Thermal Receipt Printer - 80mm أو 58mm).

قارئ باركود (1D/2D Barcode Scanner).

درج نقود إلكتروني (Cash Drawer) متصل بالطابعة.

طابعة ملصقات باركود (اختياري).

المتطلبات البرمجية (Software)

نظام تشغيل: Windows 10/11 أو Linux.

بيئة التشغيل: Node.js (v18+) أو Python (v3.10+).

قاعدة بيانات محلية: SQLite أو PostgreSQL.

🏗️ معمارية النظام والتقنيات المقترحة

لضمان عمل النظام بكفاءة عالية حتى عند انقطاع الإنترنت، يُنصح بالبنية التالية:

واجهة المستخدم (Frontend): React.js أو Vue.js مع Tailwind CSS لتصميم عصري وسريع.

تطبيق سطح المكتب (Desktop Wrapper): Electron.js أو Tauri لتحويل تطبيق الويب إلى برنامج سطح مكتب يتحكم في الطابعات ودرج النقود مباشرة.

الخلفية (Backend): Node.js (Express / NestJS) أو Python (FastAPI).

قاعدة البيانات (Database):

SQLite للتخزين المحلي السريع بدون إنترنت.

PostgreSQL أو Supabase للمزامنة السحابية ومتابعة المحل عن بُعد.

🗄️ تصميم قاعدة البيانات (Database Schema)

تتكون قاعدة البيانات الأساسية من الجداول الرئيسية التالية:

users: (id, name, username, password_hash, role, created_at)

categories: (id, name, description)

products: (id, barcode, name, category_id, cost_price, sell_price, stock_quantity, min_stock_alert, expiry_date)

customers: (id, name, phone, total_debt, credit_limit)

suppliers: (id, name, company, phone, balance)

sales: (id, invoice_number, user_id, customer_id, subtotal, discount, tax, total_amount, payment_method, status, created_at)

sale_items: (id, sale_id, product_id, quantity, unit_price, subtotal)

purchases: (id, supplier_id, total_amount, paid_amount, created_at)

cash_registers: (id, user_id, opening_balance, closing_balance, opened_at, closed_at)

🗺️ خارطة طريق التطوير (Roadmap)

[ ] المرحلة 1 (التأسيس): إعداد بيئة العمل وبناء قاعدة البيانات ونظام تسجيل الدخول.

[ ] المرحلة 2 (المخزون): برمجة شاشات إضافة المنتجات، التصنيفات، وطباعة الباركود.

[ ] المرحلة 3 (نقطة البيع): تصميم واجهة الكاشير السريعة، ربط قارئ الباركود، وبرمجة منطق الفواتير.

[ ] المرحلة 4 (الأجهزة): ربط الطابعة الحرارية ودرج النقود عبر ESC/POS.

[ ] المرحلة 5 (المالية والتقارير): إضافة نظام الديون، إغلاق الصندوق اليومي، وتقارير الأرباح.

[ ] المرحلة 6 (الاختبار والنشر): تجربة النظام في بيئة عمل حقيقية، تفعيل النسخ الاحتياطي التلقائي، وإصدار النسخة النهائية.
